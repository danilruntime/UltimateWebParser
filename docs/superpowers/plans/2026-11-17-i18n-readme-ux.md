# i18n (ru/en), bot UX, fresh Telegram, README rewrite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Перевести весь человекочитаемый слой сервиса (бот, CLI, отчёты, имена колонок парсеров) на переключаемые ru/en, не отвечать на устаревшие апдейты Telegram после перезапуска, привести вёрстку сообщений и кнопок к единому виду, и переписать README под self-hoster'а.

**Architecture:** Новый пакет `uwp.i18n` с каталогом `{Lang: {key: template}}`, разрезанным по доменам (`bot`, `cli`, `reports`) — у каждой волны свой файл, поэтому задачи не пересекаются. Язык админа хранится в `admins.language` (nullable, миграция 006) и подставляется middleware в `data["lang"]`; отчёты берут язык из `UWP_REPORT_LANGUAGE` (fallback `UWP_DEFAULT_LANGUAGE`), потому что их пишет worker, у которого нет контекста админа. Разметка остаётся HTML (уже включена глобально), меняется только структура и подписи.

**Tech Stack:** Python 3.12+, aiogram 3.31, pydantic-settings, aiosqlite, odfpy, pytest.

**Spec:** `docs/superpowers/specs/2026-11-13-ultimate-web-parser-design.md` (общая архитектура), `2026-11-14-persistent-menu-and-vnc-desktop-design.md` (меню бота), `2026-11-16-volatile-columns-in-changes-mode-design.md` (колонки отчёта). Решения этой итерации — в разделе «Approaches» ниже.

## Global Constraints

- **Русский и английский — оба полноценные.** Ни один пользовательский текст не остаётся только на одном языке. Английский не должен «протекать» в русскую локаль и наоборот.
- **`t()` бросает `KeyError` на пропущенном ключе.** Никаких fallback-заглушек вида `bot.menu.sites` в чате.
- **Идентификаторы, docstring'и и комментарии — английские.** Переводу подлежат только строки для человека.
- **Миграции append-only.** Новый файл `006_admin_language.sql`; `001`–`005` не редактируются.
- **Весь SQL — в `db/repo/`.**
- **Даты — UTC в БД, локально только на выводе** (`timeutil`).
- **Строка ≤ 88 символов** там, где это уже так; `ruff check src tests` — единственный линт-гейт, `ruff format` не запускать.
- **TDD.** Каждый шаг: падающий тест → минимальная реализация → зелёный тест.
- **Разметка — HTML** (`DefaultBotProperties(parse_mode=ParseMode.HTML)` уже стоит). MarkdownV2 не вводить.
- **Каждый README — в двух языках**, порядок и вложенность заголовков совпадают (`tests/unit/test_readme_translations.py`).
- **Не трогать:** `UWP_SECRET_KEY`, `--no-sandbox`, `proxybridge._is_internal_host`, seccomp-профиль, `vnc._port_is_free`/`_wait_for_websockify`.
- **Проверка каждой задачи:** `.venv/bin/python -m pytest <файлы> -q` и `.venv/bin/python -m ruff check src tests`.
- **Никаких `pip install` в системный интерпретатор**, только `.venv`.

## Approaches

1. **Каталог в коде (выбрано).** `uwp.i18n` с dict-каталогами, разрезанными по доменам. Плюсы: нулевые зависимости, `KeyError` на пропуске, паритет ru/en проверяется тестом, файлы не конфликтуют между задачами. Минус: перевод живёт рядом с кодом, а не в `.po`/`.json` — для двух языков это дешевле, чем тащить gettext.
2. **gettext/`.po` + babel.** Индустриально, но добавляет компиляцию `.mo` в Docker, ломает `importlib.resources`-пакет миграций и требует правок в `pyproject`. Для двух языков — лишний вес.
3. **Отдельные модули `texts_ru.py`/`texts_en.py`.** Дублирование структуры, паритет не проверяется автоматически, при добавлении ключа легко забыть вторую сторону. Каталог с одним источником структуры лучше.

Отчётный язык: **глобальная настройка**, не per-admin. Отчёт пишет worker; протаскивать язык в `runs` ради косметики — лишняя миграция и связность.

`LICENSE`: файл корректен (`Copyright (c) 2026 danilruntime`). `Copyright [yyyy] [name of copyright owner]` в `THIRD_PARTY_NOTICES.md:318` — дословный Appendix Apache-2.0 (лицензия Docker, Inc.), его нельзя заполнять. Добавляем пояснение и тест, запрещающий «починку».

## Review Focus

- **Локаль в middleware при отсутствии записи в БД.** Новый админ (только из `UWP_ADMIN_IDS`) не имеет строки в `admins`; язык должен взяться из `language_code`, а не упасть на `None`.
- **Гонка миграции и первого чтения языка.** `language()` вызывается из middleware на каждом апдейте; на только что мигрированной БД колонка есть, но значение `NULL` — это «нет мнения», а не ошибка.
- **`t()` с фигурными скобками в тексте.** Шаблоны с `{name}` форматируются, тексты без плейсхолдеров не должны падать на `.format()`.
- **Экранирование HTML после перевода.** `esc()` обязателен для имён сайтов/профилей/прокси в обеих локалях; перевод не должен добавлять `<b>` туда, где подставляется пользовательская строка.
- **`drop_pending_updates` не должен ломать graceful stop.** Вызов `delete_webhook` идёт до `start_polling`; при выключенном флаге не делается вовсе.
- **Имена листов `.ods` в английской локали.** Автофильтр строится по имени листа — `$Данные.A1:$Данные.C2` превращается в `$Data.A1:$Data.C2`; тест должен проверять согласованность, а не хардкод русского.

`__init__.py`:

```python
class Lang(StrEnum):
    ru = "ru"
    en = "en"

DEFAULT_LANG = Lang.ru
SUPPORTED: tuple[str, ...] = ("ru", "en")

def normalize(code: str | None) -> Lang | None:
    """Telegram's language_code → our Lang, or None when we do not translate it."""
    if not code:
        return None
    base = code.split("-")[0].strip().lower()
    return Lang(base) if base in SUPPORTED else None

def t(lang: Lang | str, key: str, **kwargs: object) -> str:
    catalogue = _catalog()
    try:
        template = catalogue[Lang(lang)][key]
    except KeyError:
        raise KeyError(f"missing translation: {key} [{lang}]") from None
    return template.format(**kwargs) if kwargs else template
```

`_catalog()` — `functools.lru_cache`, собирает модули `bot`, `cli`, `reports`; пересечение ключей между модулями — `RuntimeError` (иначе один домен молча перетирает другой).
