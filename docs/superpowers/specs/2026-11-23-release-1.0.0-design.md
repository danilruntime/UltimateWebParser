# Выпуск 1.0.0: установка, дисклеймер и починка дефектов — дизайн

Дата: 2026-11-23
Статус: утверждён

## 1. Зачем

Проект дошёл до состояния, в котором его можно ставить не только автору:
Steam и SoundCloud проходят на живом развёртывании, миграции append-only,
тесты зелёные. Но страница проекта обещает `0.1 beta`, не говорит ни слова про
Windows, не содержит инструкции по установке и нигде не предупреждает, что
парсер нельзя применять там, где это запрещено.

Перед `1.0.0` нужно закрыть три вещи, и только они:

1. Реальные дефекты, найденные при чтении кода (ниже).
2. Документация: установка на Linux и Windows, дисклеймер, честный статус.
3. Механика выпуска: `scripts/release.sh` не умеет ни `1.0.0`, ни перехода на
   новую мажорную линию.

## 2. Что входит

- Исправление четырёх дефектов, каждый — с падающим тестом первым:
  - `Dockerfile` healthcheck без `--offline`;
  - гонка `Database.migrate()` между ботом и воркером в split-режиме;
  - `_is_internal_host` пропускает неканонические IPv4 (`127.1`, `0x7f000001`,
    `2130706433`, `0177.0.0.1`);
  - `resolve_browser()` советует `uwp browser install`, но не говорит, что
    после неё нужен `UWP_BROWSER_PATH`, — совет замыкается в круг.
- `scripts/release.sh`: трёхчастные версии, виды `patch` и `major`, таблица
  переходов в тестах.
- Версия `1.0.0` в `pyproject.toml`, `src/uwp/__init__.py` и обоих README,
  страница `docs/releases/v1.0.0.md` (пишется вручную: скрипт коммитит и пушит
  тег, это отдельный шаг оператора).
- `docs/install.md` + `docs/install.ru.md`: Linux (Docker Engine + Compose v2) и
  Windows (Docker Desktop + WSL 2), с разделом «почему нативный запуск в
  Windows не поддерживается».
- `DISCLAIMER.md` + `DISCLAIMER.ru.md`: законное использование, ToS и robots,
  никакого обхода капчи, персональные данные, ответственность оператора.
- Обе пары — в `PAIRS` теста переводов, ссылки — из README-двойников,
  `docs/README*.md` и `/help` бота.

## 3. Что не входит

- Удаление мёртвой ветки `VNC_READY`. Бот отвечает ссылкой прямо в
  `start_login`, событие не отправляется ниоткуда, но удаление — рефакторинг,
  а `delivery` обязан терпеть неизвестные виды событий. Ветка остаётся.
- Нативный запуск в Windows. Браузер — Linux-сборка ELF, VNC-стек
  (Xvfb/x11vnc/fluxbox/websockify) и seccomp — Linux-механизмы; «поддержать»
  это значило бы написать второй продукт.
- Переписывание README «с нуля»: страница уже упорядочена (12 разделов,
  быстрый старт выше первого экрана), правки точечные.
- `ruff format` и переформатирование существующих файлов.

## 4. Подходы

**A. Только документация и бамп версии.** Дешево, но выпуск `1.0.0` с
healthcheck, который врёт о себе, и с гонкой миграций на первом старте —
это обещание стабильности, которого код не выполняет. Отброшен.

**B. Документация + четыре дефекта с тестами + механика выпуска.** Каждое
исправление маленькое, локальное и проверяемое; ничего не переписывается.
Выбран.

**C. Рефакторинг `migrate()`, `proxybridge` и `release.sh` «как правильно»,
с удалением мёртвых веток.** Даёт более чистый код, но трогает то, что не
сломано, и размывает диф перед релизом. Отброшен.

## 5. Решения

### Версии в `release.sh`

Грамматика: `X.Y` или `X.Y.Z`, необязательный суффикс `bN`. Каноническая
запись PEP 440; `0.1 beta`, `v0.1`, `1` и `0.1.0.0` отвергаются.

| вид | из | в | смысл |
| --- | --- | --- | --- |
| `beta` | `0.1b1` | `0.1b2` | следующая бета той же линии |
| `beta` | `1.0.1b1` | `1.0.1b2` | то же для трёхчастной |
| `beta` | `0.1` | `0.2b1` | бета позади своего стабильного — это даунгрейд |
| `beta` | `1.0.1` | `1.1.0b1` | следующая минорная линия бетой |
| `release` | `0.1b3` | `0.1` | снять бету, число частей сохраняется |
| `release` | `1.0.0b1` | `1.0.0` | то же |
| `minor` | `1.2.3b1` | `1.3.0b1` | новая минорная, патч обнуляется |
| `patch` | `1.0.0` | `1.0.1b1` | новая патч-линия бетой |
| `major` | `0.1b3` | `1.0.0` | новая мажорная линия, сразу стабильная |

`major` — единственный вид, который выдаёт стабильную версию сразу: `0.1b3`
и есть бета того, что становится `1.0.0`. Для следующих мажорных линий
(`1.x` → `2.0.0`) тот же вид снова даёт стабильную; бета мажорной линии
делается как `beta` от `X.Y.Z`, если понадобится, — отдельного вида нет.

`patch` требует трёхчастную версию: у `0.1` нет номера патча, и придумывать
его молча — хуже, чем отказать.

### Гонка миграций

`executescript` в Python неявно коммитит открытую транзакцию, поэтому
удержать `BEGIN IMMEDIATE` через весь скрипт нельзя: гард «прочитал
`MAX(version)` → применил» распадается на два шага. Разбивать SQL на
операторы самому — хрупко (строки, комментарии, будущие триггеры).

Решение: межпроцессный `fcntl.flock` на файле `<db>.migrate.lock` рядом с
базой, только для файловой базы (`:memory:` — тесты, там один процесс).
Это честно выражает контракт: одна машина, один каталог `./data`, миграции
применяет один процесс за раз. Внутри — существующая атомарность на
миграцию (`BEGIN IMMEDIATE … COMMIT` вокруг скрипта и записи версии).

Альтернативы: уникальный индекс на `schema_version` с `INSERT` до скрипта
(версия записана, скрипт упал — база объявлена мигрированной) и разбор SQL по
`sqlite3.complete_statement` (сложно и всё равно не даёт блокировки на запись
для второго процесса). Обе отброшены.

### Неканонический IPv4 в мосте

`ipaddress.ip_address` понимает только каноническую запись. Chromium передаёт
мосту то, что напечатал сам, а `inet_aton` в glibc принимает `127.1`,
`0x7f000001`, `0177.0.0.1` и `2130706433`. Поэтому после неудачи `ipaddress`
хост пробуется через `socket.inet_aton` и приводится к `IPv4Address`; всё,
что разбирается хоть одним способом во внутренний адрес, отвергается.
Скобки IPv6 снимаются в самой функции, чтобы гард не зависел от того, кто его
позвал.

### Документация

Установка — отдельный документ, а не раздел README: Windows требует
пошаговой инструкции, а README остаётся страницей «что это и зачем».
README получает абзац с двумя ссылками (Linux и Windows) и короткий раздел о
законном использовании перед лицензией. Дисклеймер — отдельный файл, потому
что на него ссылаются и README, и `SECURITY.md`, и бот.

Windows: Docker Desktop с бэкендом WSL 2, клон внутри файловой системы WSL
(не `/mnt/c`), порты compose уже опубликованы на `127.0.0.1` и видны в Windows
как `localhost`, Telegram-прокси на хосте доступен как `host.docker.internal`.
Нативный запуск не поддерживается: Linux-сборка браузера, Xvfb/x11vnc/fluxbox,
seccomp, `setpriv`, `flock` и права `0600/0700`.

## 6. Проверка

`pytest`, `ruff check src tests`, `bash -n scripts/release.sh`, проверка
локальных ссылок из `.github/workflows/tests.yml`, `docker compose … config -q`
если доступен Docker. Каждый дефект закрывается тестом, который падал до
правки.
