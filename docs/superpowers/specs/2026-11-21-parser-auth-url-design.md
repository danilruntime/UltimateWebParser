# Auth-URL в парсере: вход в профиль открывает страницу входа — дизайн

Дата: 2026-11-21
Статус: утверждена 2026-11-21

## 1. Зачем

Сейчас VNC-вход берёт `BaseParser.url` — URL *прогона* (у Steam это страница
поиска со скидками). Этот же URL уходит в метаданные `.ods`, поэтому подменить
его страницей входа нельзя. А «🖥 Войти» с карточки профиля не передаёт сайт
вообще, и `VncService` открывает `FALLBACK_URL = "https://example.com"` —
замерено: админ создаёт профиль, жмёт «Войти» и получает пустую страницу
example.com вместо формы входа.

Нужно: парсер объявляет страницу входа отдельно от страницы прогона, а вход
всегда открывает реальный сайт, а не заглушку.

## 2. Что должно получиться

- `BaseParser.auth_url` — страница входа; пустая означает «взять `url`», так
  что сторонний парсер без нового атрибута продолжает работать.
- `BaseParser.url` остаётся URL прогона и единственным источником
  `report.meta.url`.
- «🖥 Войти в профиль» с карточки сайта открывает `auth_url` парсера этого
  сайта и берёт прокси сайта.
- «🖥 Войти» с карточки профиля открывает страницу входа того сайта, к
  которому привязан профиль (`sites.profile_id`), и берёт прокси этого сайта.
- Если профиль не привязан ни к одному сайту — внятный отказ в языке читателя,
  а не example.com.
- `example.com` как URL входа исчезает из кода.

## 3. Не-цели

- Экран выбора сайта при входе из профиля (вариант A): админ выбрал B —
  вход идёт от карточки сайта, если привязки нет.
- Колонка `profiles.site_id` (вариант C): связь site→profile уже есть, вторая
  копия разошлась бы с первой.
- Изменение `requires_login`: он про то, нужны ли cookie прогону, а не про то,
  есть ли у сайта форма входа.
- Автоматический вход и хранение логина/пароля: по-прежнему руками.

## 4. Подходы

**A. `auth_url` + выбор сайта при входе из профиля.** Работает и без привязки,
но добавляет экран выбора и лишний клик в самом частом случае (один сайт).
Отложено: B решает ту же задачу без нового UI.

**B. `auth_url` + вход из профиля только через привязанный сайт (выбран).**
Меньше кода и никакой неоднозначности: страница и прокси берутся у одного
конкретного сайта. Цена: свежесозданный профиль сперва надо привязать к сайту.

**C. Сайт в профиле (миграция).** Дублирует `sites.profile_id`; профиль,
привязанный к двум сайтам, всё равно неоднозначен. Отвергнуто.

## 5. Как это устроено

### Парсер

```python
class BaseParser(ABC):
    url: str
    auth_url: str = ""

    @property
    def login_url(self) -> str:
        """The page a VNC login opens: ``auth_url`` or the run ``url``."""
        return self.auth_url or self.url
```

`steam_deals` объявляет `auth_url = "https://store.steampowered.com/login/"`
(проверено: отвечает 200).

### Сборка

`app.py` передаёт в `VncService` `parser_auth_urls={p.key: p.login_url ...}` —
параметр `parser_urls` переименован, потому что теперь он про вход, а не про
прогон.

### Сервис

`VncService.request(profile_id, site_id=None)`:

1. `site_id` задан → сайт из репозитория; URL — `parser_auth_urls[site.parser_key]`,
   прокси — сайта, иначе профиля.
2. `site_id` не задан → `SitesRepo.by_profile(profile_id)`:
   - ровно один сайт → он и используется (URL + прокси);
   - ноль сайтов → `ValueError` с `error.vnc.profile_without_site`;
   - больше одного → `ValueError` с `error.vnc.profile_many_sites` (войти с
     карточки нужного сайта): разные сайты могут иметь разные прокси, и
     угадывать нельзя.
3. Парсер сайта не зарегистрирован (сломан или удалён) →
   `ValueError` с `error.vnc.site_parser_unavailable`.

Отказы — готовые предложения на языке читателя, как у существующего
`error.profile.not_found`: `coded_error` в боте пропускает их как есть, CLI
печатает через `❌`.

`SitesRepo.by_profile(profile_id)` — новый метод, SQL остаётся в репозитории:
`SELECT * FROM sites WHERE profile_id = ? ORDER BY id`.

### CLI

`uwp profile login <id>` получает `--site <slug>`: без привязки профиля иначе
войти нельзя вообще. Слаг ищется среди сайтов, `site_id` передаётся в сервис.

## 6. Что решает исполнитель

- Текст трёх новых ключей `error.vnc.*` в обоих языках.
- Достаточно ли `ORDER BY id` для выбора «первого» сайта (нет: при нескольких
  сайтах сервис отказывает).
- Обновление README, README.ru, docs/README(.ru), README парсера Steam и
  инварианта в `AGENTS.md`.

## 7. Проверки

- `BaseParser.login_url` без `auth_url` возвращает `url`; с `auth_url` — его.
- `steam_deals.auth_url` — страница входа Steam.
- VNC с `site_id` открывает auth-URL, а не search-URL.
- VNC из профиля с привязанным сайтом открывает auth-URL и берёт прокси сайта.
- VNC из профиля без привязки — отказ в ru и en, без запуска стека.
- VNC из профиля с двумя сайтами — отказ, без запуска стека.
- Метаданные `.ods` по-прежнему содержат `parser.url`, а не `auth_url`.
- Бот: «Войти» из профиля без привязки отвечает `show_alert` в языке читателя.
- CLI: `profile login` без привязки печатает отказ; с `--site` — открывает.
- `ruff check src tests` и полный `pytest` зелёные.
