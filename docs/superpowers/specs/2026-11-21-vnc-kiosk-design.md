# VNC-киоск: одно окно, без панели, меню и DevTools — дизайн

Дата: 2026-11-21
Статус: на утверждении

## 1. Зачем

VNC-ссылка сейчас открывает полноценный рабочий стол: панель задач fluxbox,
контекстное меню с запуском приложений, обычное окно Chromium с вкладками,
адресной строкой и DevTools по F12. Админ, который входит по этой ссылке,
получает больше, чем нужно для задачи «войти в аккаунт на сайте»: он может
открыть настройки, историю, загрузки, файловую систему и консоль разработчика.

Нужно оставить ровно одно: страницу сайта, в которой можно ввести логин и
пароль. `fluxbox` при этом остаётся — он управляет окном и, что важнее,
перехватывает клавиатуру.

## 2. Что должно получиться

- В VNC видно одно окно Chromium на всю область экрана: без вкладок, без
  адресной строки, без кнопок и меню браузера.
- Нет панели задач, нет меню рабочего стола, нет заголовков окон.
- DevTools не открывается ни клавишами, ни из меню.
- Страница работает: поля ввода, пароли, капчи, кнопки, редиректы после входа.
- `fluxbox` остаётся в стеке.
- Выход из сессии по-прежнему только через бота («Готово») или по таймауту.

## 3. Не-цели

- Защита от человека, который уже получил управление процессом Chromium:
  VNC отдаёт пиксели и события ввода, а не права.
- Отдельный контейнер или отдельный uid для браузера входа. Это следующий шаг,
  если VNC-ссылку будут давать не админу.
- Запрет OAuth-попапов как отдельная фича: kiosk-режим сам сводит `target=_blank`
  к навигации в том же окне (замерено), ломать вход мы не будем.
- Политики Chromium (`/etc/chromium/policies/…`). Замерено: политика
  `DeveloperToolsAvailability=2` валит `launch_persistent_context` (180 с
  таймаута), то есть останавливает парсеры. Политика машинная, а не на профиль,
  поэтому «только для VNC-браузера» её не включить.

## 4. Ограничения, проверенные на образе

Всё ниже замерено на живом контейнере `uwp-worker`, не взято из документации.

| Что проверяли | Результат |
| --- | --- |
| `--app=<url>`, обычное окно | вкладок и адресной строки нет, но **Ctrl+N и Ctrl+T открывают новые окна** (окон 3 → 4 → 5); DevTools открывается по Ctrl+Shift+I (скриншот с панелью Elements) |
| `--kiosk <url>` | вкладок, адресной строки, меню и контекстного меню нет; DevTools по Ctrl+Shift+I Chromium закрывает сам: «DevTools not allowed on this page» |
| `--kiosk` без `--window-size` | **окно 945×1060 в углу** (замерено в собранном стеке): `--fingerprint` игнорирует геометрию kiosk |
| `--kiosk` + `--window-size=1920,1080` | окно ровно 1920×1080, без декораций |
| `--kiosk`, Ctrl+T | нового окна нет |
| `--kiosk`, Ctrl+N | **дыра: открывается обычное окно 1050×760 с полным UI** |
| `--kiosk`, клик по `<input type=file>` | диалог выбора файла не открывается — до `data/` не добраться |
| `--kiosk`, `window.open` без клика | попап не создаётся |
| `--kiosk`, клик по `target=_blank` | страница грузится в том же окне (замерено: «CHILD OAUTH» занял экран, окон по-прежнему 2) |
| `--kiosk`, правый клик по странице и по полю ввода | меню не появляется; левый клик при этом доходит (переход по кнопке сработал) |
| fluxbox `keys` c `Control Shift i :Exec true` и `F12 :Exec true` | Ctrl+Shift+I и F12 до Chromium не доходят; **неперехваченный** Ctrl+Shift+J DevTools открывает |
| fluxbox `keys` с 20 сочетаниями | ни одного нового окна, ни одного изменения пикселей за весь прогон |
| `session.screen0.toolbar.visible: false` | панели нет |
| пустой `session.menuFile` | правый клик по столу не даёт меню |
| `--disable-dev-tools` | эффекта не даёт, флага в этом билде нет |
| политика `DeveloperToolsAvailability=2` | применяется (диалог «blocked»), но ломает Playwright; безобидная `BookmarkBarEnabled` не ломает |

Вывод: пару «kiosk + grab'ы fluxbox» нельзя заменить ни одним флагом в
отдельности — каждое по отдельности оставляет окно или DevTools.

## 5. Решение

### 5.1 Браузер входа

`--kiosk <url>` вместо `--app`. Размер окна по-прежнему задаётся явно
(`--window-size=1920,1080`, `--window-position=0,0`), но теперь он равен экрану:
замерено, что kiosk вместе с `--fingerprint` встаёт окном 945×1060 в углу, как
когда-то `--start-maximized`. `WORKAREA` и `TASKBAR_HEIGHT` удалены, потому что
панели больше нет; `DESKTOP_SIZE` остался и используется и для Xvfb, и для
`--window-size`.

Проверенный `playwright.launch` парсеров не меняется: kiosk — это аргумент
только VNC-стека.

### 5.2 fluxbox: без панели, без меню, с перехватом

`_write_fluxbox_home` пишет три файла вместо двух:

- `init` — `session.screen0.defaultDeco: NONE`, `toolbar.visible: false`,
  `session.menuFile` на пустой файл, `session.keyFile` на наш `keys`,
  один рабочий стол;
- `apps` — прежнее правило `[Deco] {NONE}` для `class=Chromium` как вторая
  линия защиты (оно проигрывает гонку, но стоит ноль);
- `menu` — пустой;
- `keys` — по строке `Сочетание :Exec true` на каждое опасное сочетание.

`:Exec true` — проверенная пустышка: `:Noop`, `:None`, `:MacroCmd` fluxbox
считает синтаксической ошибкой («Invalid key/modifier»), а `:Exec true`
молча запускает `/bin/true` и съедает сочетание.

Список перехвата (все проверены в матрице):

```
Ctrl+N, Ctrl+Shift+N   новое окно / инкогнито
Ctrl+T, Ctrl+Shift+T   новая вкладка / вернуть закрытую
Ctrl+W, Ctrl+Shift+W   закрыть вкладку / окно
Ctrl+Shift+Q           выход из браузера
Alt+F4                 закрыть окно
Ctrl+Shift+I/J/C, F12  DevTools и инспектор
Ctrl+U                 исходник страницы
Ctrl+S, Ctrl+P, Ctrl+O сохранить / печать / открыть файл
Ctrl+H, Ctrl+J         история / загрузки
Ctrl+D, Ctrl+Shift+O,  закладки
Ctrl+Shift+B
Ctrl+L, Ctrl+K, Ctrl+E, адресная строка и поиск
Alt+D, F6
Ctrl+F, F3, Ctrl+G     поиск по странице
F11                    полноэкранный режим
F1                     справка
Ctrl+Shift+Delete      очистка данных
Ctrl+Shift+M           меню профиля
Shift+F10, Menu        контекстное меню с клавиатуры
Ctrl+±, Ctrl+0         зум
Alt+Home               домашняя страница
```

Намеренно **не** перехватываются: `F5`/`Ctrl+R` (перезагрузка страницы) и
`Alt+←`/`Alt+→` (назад/вперёд) — это управление самой вкладкой, без них
незавершённый вход не переиграть. Печать, буфер обмена и Tab/Enter не трогаем.

### 5.3 Что остаётся за границей решения

Честно: это UI-защита, а не песочница. Секреты воркера посетителю уже
недоступны (`browser_env` allowlist, `PR_SET_DUMPABLE=0`), рендерер работает в
sandbox. Киоск убирает двери, а не стены: если какая-то комбинация Chromium не
попала в список, она доедет до браузера. Поэтому список — данные в модуле, а не
строчки внутри функции, и тест сверяет его с известным набором.

Второй слой на будущее, если ссылку будут отдавать не админу: отдельный uid для
браузера входа и запрет чтения `/data` кроме своего профиля. В этот дизайн не
входит.

## 7. Тесты

Сначала падающие:

1. `test_browser_runs_in_kiosk_mode` — в команде браузера есть `--kiosk`, а
   `--window-size` равен экрану (`1920,1080`), не рабочей области.
2. `test_fluxbox_home_hides_the_panel_and_menu` — `toolbar.visible: false`,
   `menuFile` на пустой файл, `keyFile` на наш, файл `menu` пуст.
3. `test_fluxbox_grabs_every_escape_chord` — для каждого сочетания из эталона
   есть строка `:Exec true`; ни одно не задано командой, отличной от `true`.
4. `test_fluxbox_leaves_the_page_keys_alone` — `F5`, `Control r`, `Mod1 Left`,
   `Mod1 Right` отсутствуют в `keys`.
5. `test_fluxbox_keys_parse` — файл не содержит `:Noop`/`:None`/`:MacroCmd`
   и пустых команд (замерено: fluxbox ругается «Invalid key/modifier»).

Проверка руками после сборки: открыть сессию, нажать Ctrl+N, Ctrl+Shift+I, F12,
правый клик — окно и экран не меняются; F5 перезагружает страницу; вход в
аккаунт проходит.
