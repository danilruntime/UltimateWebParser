# Своё название сайта в боте

Дата: 2026-11-20
Статус: на утверждении

## Что хотим

Админ добавляет в боте сайт и хочет назвать его по-своему: «Steam US»,
«Скидки для подарков», «Мой магазин». Сейчас `site:add:<parser>` сразу создаёт
сайт, и единственное имя — заголовок парсера («Steam — скидки»). Исправить его
из бота нельзя: `uwp site set <slug> --name` есть только в CLI.

## Решение

Выбран вариант A: спрашивать имя при добавлении и давать переименовать позже.

### Добавление

`site:add:<parser>` больше ничего не создаёт: он запоминает ключ парсера в FSM и
присылает сообщение с просьбой прислать название. Под ним две кнопки:

- «✅ Оставить по умолчанию» (`site:adddefault:<parser>`) — создаёт сайт с
  именем парсера на языке админа (как сейчас);
- «⬅️ Отмена» (`sites:list`).

Текст сообщением создаёт сайт с введённым именем. Пустая строка после `strip()`
считается ошибкой («название не может быть пустым»), а не молчаливым «по
умолчанию»: молчаливая подмена выглядит как потерянный ввод.

### Переименование

На экране настроек сайта появляется пункт «✏️ Название» (`set:name:<id>`); он
открывает тот же ввод, а сохранённое имя возвращает на экран настроек.

### Правила имени

- `strip()`; перевод строки и табы схлопываются в один пробел (Telegram
  запрещает `\n` в тексте кнопки, а имя стоит на кнопке списка сайтов);
- пустое имя отклоняется: `error.site.name_empty`;
- длиннее 64 символов отклоняется: `error.site.name_too_long`. 64 — предел
  текста inline-кнопки Telegram; без него список сайтов падает с
  `TelegramBadRequest` на длинном имени.

Проверка живёт в `services/sites.py` (`clean_site_name`), потому что через неё
проходят и бот, и CLI: `uwp site set --name` сейчас пишет в репозиторий напрямую
и пропустил бы оба ограничения.

### Что не меняется

- `slug` при переименовании не пересчитывается. На него завязаны папка отчётов
  `data/exports/<slug>/` и аргументы CLI; смена slug развела бы старые файлы и
  новые команды.
- Схема БД: `sites.name` уже есть, `SitesRepo._COLUMNS` уже умеет `name`.
- Отчёты и уведомления читают `site.name`, поэтому новое имя сразу видно в
  `.ods` и в подписи к файлу. Имя файла отчёта меняется вместе с названием,
  папка — нет.

## Границы

- Не добавляем переименование через сообщение в карточке сайта без кнопки: это
  перехватило бы любой текст и сломало бы меню.
- Не трогаем `slug`, `seed.py` и существующие имена сайтов.
- Максимальная длина — одна константа в сервисе, не в двух местах.

## Проверка

- `test_site_service.py`: обрезка пробелов, схлопывание переводов строк, пустое
  имя, 65 символов, ровно 64, `create(..., name="  Моё  ")`.
- `test_bot_language.py`: добавление спрашивает имя; кнопка «по умолчанию»
  создаёт сайт с именем парсера на языке админа (существующий тест
  `test_adding_a_site_stores_the_name_in_the_admins_language` переносится на
  эту кнопку); имя, отправленное текстом, сохраняется; «✏️ Название»
  переименовывает и возвращает на настройки.
- `test_settings_parse.py`: в `settings_kb` появляется `set:name:<id>`.
- `test_i18n.py` сам поймает рассинхрон ключей ru/en.
- `ruff check src tests`.
